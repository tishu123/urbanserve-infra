# UrbanServe on AWS (Terraform)

Two cost profiles from the same code. **Lean is the default**, sized to run on the AWS
new-account credits ($100 + up to $100 more) for ~6 months until you have customers.

```
LEAN (default)                                         SCALE (flip the switches later)
Browser ─HTTPS─▶ CloudFront ─▶ S3 (React, private/OAC)  Browser ─▶ WAF ─▶ CloudFront ─▶ S3
                     │                                                      │
                     └─/api/*─▶ EC2 :8080 (Elastic IP)                      └─/api/*─▶ ALB ─▶ EC2
                                 ├ Spring Boot                                                 │
                                 └ PostgreSQL (localhost, own EBS disk) ─▶ nightly backup to S3 └▶ RDS
```

| Switch | Lean (default) | Scale |
|---|---|---|
| `use_alb` | `false` → CloudFront → EC2 directly | `true` → Application Load Balancer |
| `enable_waf` | `false` | `true` → managed rules + rate limits |
| `db_mode` | `"ec2"` → PostgreSQL on the instance | `"rds"` → managed RDS |

## What it costs (Mumbai, low traffic, approximate)

| Item | Lean | Scale |
|---|---|---|
| EC2 t4g.small | ~$12 | ~$12 |
| Public IPv4 (AWS charges each one) | ~$3.65 (1 IP) | ~$11 (3 IPs) |
| EBS disks (20 GB root + 10 GB DB) | ~$2.50 | ~$2 |
| PostgreSQL | $0 (on the instance) | ~$15–18 (RDS) |
| Load balancer | $0 | ~$18 |
| WAF | $0 | ~$15 + requests |
| CloudFront, S3, SSM Parameter Store, Budgets | ~$0–1 (always-free allowances) | ~$1 |
| **Total / month** | **≈ $18–20** | **≈ $75–85** |

SMS for OTP (Message Central VerifyNow by default) is billed per message by the provider, on top of this. These are list-price estimates, so confirm with the
[AWS Pricing Calculator](https://calculator.aws/). In the lean profile, $200 in credits covers about
6 months with room left for SMS.

### Which AWS plan to choose
- **Free plan:** you can never be charged. The account closes automatically after 6 months or when
  the credits run out, and data is deleted 90 days after that. Some services may be unavailable; if a
  `terraform apply` is refused, upgrade to the Paid plan (you keep the credits).
  **Set a reminder to upgrade before month 6, or the site goes down.**
- **Paid plan:** same credits, and nothing shuts down when they end. Normal billing starts instead,
  so the budget alert below is your safety net.

## Security (both profiles)

| Layer | Control |
|---|---|
| CloudFront | HTTPS only, HSTS, strict CSP, `X-Frame-Options: DENY`, `nosniff`, Referrer and Permissions policies. API never cached. Shield Standard DDoS protection (free, always on). |
| S3 | Private; readable only by this distribution (OAC). Encrypted, versioned, HTTPS required. |
| API origin | The security group admits **only CloudFront's origin-facing IP ranges** (an AWS-managed list), plus a **secret `X-Origin-Verify` header** that the Spring app (and the ALB, if used) checks. Direct calls get 403. |
| EC2 | No SSH or port 22 (use SSM Session Manager). IMDSv2 required, encrypted disks, non-root sandboxed service. |
| Database | Lean: PostgreSQL listens on **localhost only**, password auth, on its own encrypted disk with nightly `pg_dump` to S3 (kept 30 days). RDS: private, TLS enforced, automated backups. |
| Secrets | DB password, JWT key and origin secret are generated by Terraform; the Message Central password comes from `terraform.tfvars`. All are stored in **SSM Parameter Store (SecureString, KMS-encrypted)**, read at service start, never baked into the server image. |
| Auth | Phone OTP, then a 24 h JWT. Per-phone OTP limits in the app. WAF adds per-IP limits when enabled. |
| WAF (optional) | IP reputation, common/OWASP rules, known bad inputs, SQLi, rate limits for API, site and OTP, country and IP blocklists. |

**Lean trade-off:** the CloudFront → EC2 hop is plain HTTP (it's still restricted by IP list and
secret header), and there's a single server. Switch to `use_alb = true` with `alb_certificate_arn`
for TLS on that hop, and to `db_mode = "rds"` once you have real traffic.

## First deploy

```bash
# 0. AWS account: enable MFA on root, create an admin IAM user / IAM Identity Center user, `aws configure`
cd terraform
cp terraform.tfvars.example terraform.tfvars   # set budget_alert_email and messagecentral_password
terraform init
terraform apply                                # ~10 min (CloudFront is the slow part)
# Confirm the AWS Budgets subscription email.

cd ..
./scripts/deploy-backend.sh  ~/Downloads/urbanserve
./scripts/deploy-frontend.sh ~/Downloads/urbanserve-web
```

Open the `site_url` output.

## Operations

- **Logs:** run `aws ssm start-session --target <app_instance_id>`, then `sudo journalctl -u urbanserve -f`
- **Bootstrap log:** `/var/log/urbanserve-bootstrap.log`
- **Back up now:** `sudo systemctl start urbanserve-backup`. Backups are stored in `s3://<artifacts_bucket>/db-backups/`.
- **Restore a backup:**
  ```bash
  aws s3 cp s3://<artifacts_bucket>/db-backups/urbanserve-<ts>.dump /tmp/db.dump
  sudo systemctl stop urbanserve
  sudo -u postgres pg_restore --clean --if-exists -d urbanserve /tmp/db.dump
  sudo systemctl start urbanserve
  ```
- **Change config** (e.g. admin phones): edit `terraform.tfvars`, run `terraform apply`, then restart the service through SSM.
- **Move to RDS later:** take a backup, set `db_mode = "rds"`, apply, `pg_restore` into RDS, restart.

## SMS for OTP (India)

### Default: Message Central VerifyNow (`otp_sender = "messagecentral"`)
Message Central sends the OTP from its own DLT-registered sender and template and checks the code
itself, so **no DLT registration of your own** and no SNS sandbox.
1. In `terraform.tfvars` set `messagecentral_password` (the customer ID defaults to `C-DC8D1C144CA446C`).
   Prefer not to keep it in a file? `export TF_VAR_messagecentral_password='...'` before `terraform apply`.
2. `terraform apply`, then restart the service (or run `deploy-backend.sh`, which restarts it).
3. Check: `sudo journalctl -u urbanserve | grep "OTP sender"` should show
   `Message Central VerifyNow (SMS), customerId=...`.
4. Keep the Message Central wallet topped up; OTPs stop when the balance runs out.
5. Changing the password later: update `terraform.tfvars`, `terraform apply`, restart the service.

The SMS text and sender name are Message Central's, not "UrbanServe". For your own branding, switch to SNS below.

### Alternative: Amazon SNS with your own DLT registration (`otp_sender = "sns"`)
1. **DLT registration (TRAI):** register your entity, a 6-letter sender ID and an OTP template matching
   `app.otp.message`. Put the IDs in `terraform.tfvars`.
2. **SNS sandbox:** new accounts can text only verified numbers. Add test numbers in SNS → Text messaging,
   then request production access and a higher spend limit.

### Testing without SMS
Set `otp_sender = "log"`; codes appear in `journalctl -u urbanserve | grep "DEV OTP"`.

## Custom domain
Request an ACM certificate **in us-east-1**, set `domain_aliases` and `cloudfront_certificate_arn`, apply,
then point your DNS at the `cloudfront_domain` output.

## Known gaps
- **Single instance.** Move to an Auto Scaling group across 2 AZs (with RDS) for high availability.
- **DB password rotation is manual.** Run `terraform apply -replace=random_password.db`, then restart the service (lean mode re-syncs the role on reboot).
- **Logout doesn't revoke tokens.** JWTs stay valid until they expire (24 h).
- **Remote state.** Uncomment the S3 backend in `versions.tf`. The state contains secrets, so keep it private and encrypted.
- **`terraform destroy` stops at the DB data disk.** This is on purpose (`prevent_destroy`), so customer data isn't lost by accident.
